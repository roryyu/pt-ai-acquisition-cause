# 洞察画布整合改造

## 背景与目标
`pt-ai-acquisition-cause` 中洞察报告（reports）、看板（boards）、日报（digests）三个模块功能高度重叠且画布能力弱。本次改造将其统一为「洞察画布」：每个产物是一份 tldraw 画布文档，可导入数据分析（`/ask`）与深度研究（`/research`）的结果作为"实时绑定"形状，用户可自由编辑标注，支持导出 PNG、走邮件发送与定时任务抽象层。

## 数据模型（prisma/schema.prisma + 新迁移）

新增模型（全部 `@@schema("cause")`，沿用现有命名风格）：
- `InsightDoc`（insight_docs）：`id`、`title`、`kind`（枚举 InsightDocKind：report/board/digest）、`description`、`snapshot`（Json，tldraw store snapshot）、`status`（draft/published/archived）、`createdBy`、`workspaceId`、时间戳。关联 User/Workspace。
- `CanvasBinding`（canvas_bindings）：`id`、`docId`（级联删除）、`shapeId`（对应画布上的形状 id）、`sourceType`（question/research/metric）、`sourceId`（question_xxx / task_xxx 或 null）、`query`（Json，可选：绑定的重跑参数）、`payload`（Json，最新内容：ChartSpec / 指标值 / markdown 摘要 / 引用）、`sourceStatus`、`updatedAt`。
- `ScheduleJob`（schedule_jobs）：`id`、`docId`、`action`（email/export）、`cronExpr`、`recipients`（Json）、`enabled`、`lastRunAt`、`nextRunAt`。
- `DeliveryRecord`（delivery_records）：`id`、`docId`、`channel`（email/image）、`status`（queued/sent/failed）、`detail`（Json）、`createdAt`。

删除模型：`Report`、`Board`、`BoardCard`、`Digest`（含 User/Workspace 上的反向关系字段）。生成一次 Prisma 迁移（drop 旧表在迁移脚本跑完后执行，见"旧数据迁移"）。

## 后端 API（app/api/v1/）

沿用 `lib/server/api-runtime.ts` 的 `ok/handleApiError/requireActor` 模式，id 用 `newId`：
- `insights/route.ts`：GET 列表（`kind` 过滤、分页）、POST 创建（kind + title + 初始空 snapshot）。
- `insights/[id]/route.ts`：GET（含 bindings）、PUT（保存 snapshot/title/status，事务内 upsert bindings）、DELETE。
- `insights/[id]/bindings/route.ts`：POST 新增绑定（sourceType + sourceId），服务端立即拉取一次源数据填充 payload——question 从 `Question.answer` 提取 charts/tables/text；research 从 `ResearchTask.output/citations` 提取。
- `insights/bindings/[id]/route.ts`：GET 单条刷新（重新拉取源数据）、DELETE。
- `insights/[id]/export/route.ts`：POST 接收客户端 `editor.exportToBlob` 的 PNG base64，落盘到 `public/exports/{docId}-{ts}.png` 并写 DeliveryRecord（channel=image）。
- `insights/[id]/deliver/route.ts`：POST `{channel:'email', recipients}` —— 调用发送抽象层。
- `schedules/route.ts` + `schedules/[id]/route.ts`：CRUD；`schedules/run/route.ts`：POST 手动/外部 cron 触发，扫描 `nextRunAt <= now && enabled` 的任务执行（执行邮件发送或导出），更新 lastRunAt/nextRunAt（自实现 cron 表达式解析的最小实现或引入 `cron-parser` 依赖，二选一，倾向引入 cron-parser）。

删除：`reports/*`、`boards/*`、`digests/*` 全部路由。

## 发送/调度抽象层（lib/server/delivery/）

- `channel.ts`：`DeliveryChannel` 接口 `{ name; deliver(doc, snapshot, opts): Promise<DeliveryResult> }`。
- `email-channel.ts`：SMTP 未配置时降级为"落盘记录"——将渲染后的报告 HTML/图片路径写入 `.deliveries/` 目录并记 DeliveryRecord（status=sent，detail 标注 mock）。`.env` 存在 `SMTP_HOST` 等配置时预留 nodemailer 接入点（本期不装 nodemailer，只留 TODO 与接口）。
- `image-channel.ts`：保存 PNG 文件并记录。
- `lib/server/scheduler.ts`：ScheduleJob 到期判断与执行入口，供 `schedules/run` 调用；README 注明可用外部 cron 定时 `curl POST /api/v1/schedules/run`。

## tldraw 画布前端（app/(dashboard)/insights/）

依赖：`npm i tldraw`（React 19 兼容；注意 tldraw SDK 商用需许可证，作为假设记录）。

- `insights/page.tsx` + `client.tsx`：列表页，Tab 过滤 全部/报告/看板/日报，卡片展示 title/kind/更新时间，新建对话框选 kind。
- `insights/[id]/page.tsx` + `client.tsx`：画布编辑器页。`import { Tldraw } from "tldraw"` 与 `"tldraw/tldraw.css"`；`persistenceKey` 不用，改为受控：加载时 `loadSnapshot(doc.snapshot)`，编辑防抖 1.5s 后 PUT 保存；用户可直接用 tldraw 原生画笔/便签/箭头/文本做标注。
- 自定义实时形状（`components/canvas/shapes.tsx`，`createShapeShapeUtil` 注册为 `LiveContentShape`）：props 含 `bindingId`、`kind`（chart/metric/text/research）、`payload`、`updatedAt`、`live` 标志。内部用现有 `ChartRenderer`、`MarkdownView` 渲染；右上角显示"实时"徽标与更新时间；源任务未完成时显示转圈"更新中"。
- 导入面板（画布右侧抽屉）：
  - 「数据分析」列表来自 `/api/v1/ask`（最近问答），选中后 POST binding 并在画布中央创建形状；
  - 「深度研究」列表来自 `/api/v1/research`，同上导入报告摘要+引用；
  - 也可从问答页复制 ChartSpec 手动粘贴为图表形状（保留现有能力）。
- 实时刷新：画布页每 10s 轮询 bindings 接口，payload 变化则 `editor.updateShape` 更新形状 props；research/question 状态为 running 时徽标显示"更新中"。
- 工具栏扩展（tldraw `components` 覆盖 ShareMenu 区）：
  - 「导出 PNG」：`editor.exportToBlob({ format:'png' })` → 浏览器下载 + POST export 接口存档；
  - 「发送邮件」：填收件人调 deliver 接口，展示 DeliveryRecord 结果；
  - 「定时任务」：对话框配置 cron/收件人/动作，调 schedules 接口，展示该文档的任务列表与上次执行时间。

## 导航整合与清理

- `sidebar.tsx`：三个入口（洞察报告/看板/日报中心）替换为单个「洞察画布」（`/insights`，icon 用 PenTool 或 Presentation）。
- 全局检索 `/reports`、`/boards`、`/digests` 的引用（工作台 `(dashboard)/client.tsx`、boards 详情页的研究追踪等）并改指向 `/insights`。
- 删除 `app/(dashboard)/reports|boards|digests` 目录与对应 API。

## 旧数据迁移

- `scripts/migrate-insights.ts`（tsx 运行，参考现有 seed 脚本风格）：
  - reports → InsightDoc(kind=report)：markdown 文本转 text 形状、charts 数组转 chart 形状，程序化生成 tldraw snapshot JSON；
  - boards + board_cards → kind=board：按 position 网格布局生成形状；
  - digests → kind=digest；
  - 幂等（按旧 id 映射表 `old_id → new_id` 判重），打印迁移统计。
- 迁移完成并验证后，执行 Prisma 迁移 drop 旧表。

## 测试与验证

- vitest：binding payload 提取逻辑（question answer → charts/text）、schedule 到期判断、delivery 抽象层落盘行为。
- `npm run typecheck`、`npm run lint` 通过；`npm run build` 成功。
- 手动验证：启动 dev（Node v24.7.0，nvm PATH）→ 创建画布 → 导入一个已完成的研究任务与一个问答图表 → 轮询显示更新时间 → 画布上添加标注 → 保存刷新后 snapshot 恢复 → 导出 PNG → 邮件发送走 mock 落盘 → 创建定时任务并手动触发 run。

## 假设与说明

- tldraw SDK 商用需自行获取许可证，本期按开发/评估用途直接引入。
- 邮件本期为抽象层 + 落盘记录，SMTP 实装留接口待下期。
- 定时任务靠 `POST /api/v1/schedules/run` 驱动（UI 手动 + 外部 cron），不在 Next 进程内常驻定时器。
- snapshot 以 JSON 存 Postgres；用户粘贴大图可能导致体积增长，导出/保存接口加 5MB body 上限校验。
- 遵循项目规范：中文注释、API 统一 `{ok, data}` / `{error:{code,message}}` 结构、design.md 为规范源（本次为产品演进，完成后建议同步更新 design.md，属可选后续项）。
