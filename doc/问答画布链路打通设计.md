# 任务问答 → 洞察画布：业务链路打通设计

## 背景与问题

洞察画布改造（见 `画布设计.md`）已具备 CanvasBinding 实时绑定、轮询刷新、导出/投递能力，但「任务问答 → 洞察画布」的业务链路目前是断的，共 5 处断点：

| # | 断点 | 现状 |
|---|---|---|
| 1 | 无流入入口 | `/ask` 页完成问答后没有任何"进画布"动作；唯一路径是去画布页打开导入面板，从最近 12 条里人工挑选，业务动线断裂且反向 |
| 2 | 形状与绑定未真正关联 | `canvas-editor` 的 `applyBinding` 只回填 `payload/sourceStatus/updatedAt`，形状 `bindingId` 恒为空，形状与绑定无法互查 |
| 3 | 删形状不清绑定 | 画布上删除实时卡片后绑定成孤儿，轮询持续空转，文档详情返回无效绑定 |
| 4 | 删源不收敛 | 删除问答/研究任务后，指向它的绑定仍显示"实时"徽标；`refresh` 抛 404 被轮询静默吞掉，状态永久僵死 |
| 5 | 无溯源回链 | 画布卡片无法跳回原始问答上下文，洞察与证据链脱节 |

## 目标链路（打通后的闭环）

```
/ask 问答完成（流式完成态 / 历史回看）
  └─ 点「加入画布」→ 弹窗勾选图表（默认全选）+ 选中已有画布（或内联新建）并点「添加」确认
       └─ 跳转 /insights/{docId}?import=question:{qid}&charts=0,2
            └─ 画布挂载后自动：按勾选下标「一图一卡」创建实时形状 → 逐个创建绑定 → 回填 payload → 清除 URL 参数
                 ├─ 源运行中：徽标「更新中」，10s 轮询自动刷新
                 ├─ 删除形状 ⇒ 级联删除对应绑定
                 ├─ 删除源问答/研究 ⇒ 绑定标记 sourceStatus=deleted，
                 │   卡片保留最后内容、徽标「源已删除」，不再参与刷新
                 └─ 卡片头部「打开来源」⇒ /ask?q={qid} 自动加载该问答详情
```

## 详细设计

### 1. 一键流入（问答 → 画布）

- **入口**：`ask/client.tsx` 在两处出现「加入画布」按钮——
  - 流式完成态（`state.done && state.questionId` 且无错误）的完成提示行旁；
  - 历史回看 `status === completed` 时的路由横幅行。
- **画布选择弹窗**（新组件 `components/canvas/AddToCanvasDialog.tsx`，通用，接受 `sourceType: question | research`）：
  - ① 图表多选：来源有图表时展示勾选列表（类型图标 + 标题 + 类型标签），默认全选，可全选/全不选；
  - ② 画布列表：`GET /api/v1/insights?page=1&pageSize=20`，展示标题 + kind 徽标 + 绑定数；
  - 选中交互：点击行仅切换选中态（高亮 + 勾选），列表下方「添加」按钮确认后才深链跳转，避免误触行即跳离问答页；
  - 内联新建：输入标题（kind 默认 report）→ `POST /api/v1/insights` 成功后直接进入；
  - 确认后 `router.push(/insights/{docId}?import={sourceType}:{sourceId}&charts={勾选下标})`。
- **深链自动导入**：`insights/[id]/page.tsx` 读 `searchParams.import` / `searchParams.charts` 透传给编辑器；`canvas-editor` 在编辑器挂载后执行一次与导入面板相同的 `handleImport` 逻辑，成功后 `history.replaceState` 清除参数并提示"已添加 N 张图表卡片"。
  - 形状创建仍发生在画布客户端（tldraw `createShapeId`），服务端不感知形状细节，避免服务端拼接 snapshot 的脆弱性。
- **一图一卡**：`handleImport` 收到 `chartIndexes` 时按「每张图一张卡片」横向排开（宽 460 + 间距 24，整体居中于视口中心），每卡各自持有绑定（删卡级联清绑定、轮询各自刷新）；单卡绑定失败仅回滚该卡，全部失败才报错。未带下标（导入面板/研究类）时仍为整段内容一张卡片。
- **快照瘦身与保存可靠性**：落盘前 `stripLivePayload` 剔除实时卡片 props 里的 `payload`（内容以 CanvasBinding 表为准，挂载后立即回灌一次绑定，不带 `refresh=1`）；实测 2 卡快照 66KB → 3KB。`keepalive` 仅用于 beforeunload 冲刷——浏览器对 keepalive 请求体有 64KB 上限，超限直接抛 `Failed to fetch`，此前常规保存也开着 keepalive，导致稍大的画布永远停在「待保存」。
- **`/ask` 反向深链**：`ask/page.tsx` 透传 `searchParams.q`，`AskClient` 挂载时若存在则自动 `viewQuestion(q)`，支撑画布卡片溯源回跳。

### 2. 形状 ↔ 绑定关联补全

- `applyBinding` 回填 `bindingId`、`sourceType`、`sourceId` 进形状 props（绑定记录本就携带这些字段，`BindingView` 已定义）；
- `live-shape` props 扩展 `sourceType: "" | "question" | "research" | "metric"`、`sourceId: string`（均可序列化，兼容 snapshot 持久化）。

### 3. 生命周期收敛

- **删形状 ⇒ 删绑定**：`handleMount` 中现有 `store.listen` 回调内检查 `event.changes.removed`，凡 `typeName=shape && type=live-content && props.bindingId` 者，fire-and-forget `DELETE /api/v1/insights/bindings/{bindingId}`。
  - 已知边界：删除后再撤销（undo）会恢复形状但绑定已删，卡片退化为静态内容（徽标停留在最后状态）——可接受，文档注明。
- **删源 ⇒ 标记 deleted**：
  - `DELETE /api/v1/ask/[id]`：删除前 `canvasBinding.updateMany({ where: { sourceType:"question", sourceId:id }, data: { sourceStatus:"deleted" } })`；
  - `DELETE /api/v1/research/[id]`：同理标记 research 绑定，及其关联 `questionId` 的 question 绑定；
  - `GET /insights/[id]/bindings?refresh=1` 的刷新过滤排除 `deleted`（与 completed/failed 同级），避免无源刷新反复抛错。
- **展示**：`sourceStatus=deleted` 时卡片头部灰色徽标「源已删除」，正文保留最后一次 payload；`isSourceRunning` 对 deleted 返回 false。

### 4. 溯源回链

- `live-shape` 卡片头部：当 `sourceId` 存在时显示「打开来源」图标按钮（`onPointerDown` stopPropagation 避免触发 tldraw 拖拽）：
  - `question` → `/ask?q={sourceId}`；
  - `research` → `/research`（研究页详情参数化留待后续）。

### 5. 类型与状态助手（`lib/canvas/types.ts`）

- `sourceStatusLabel` 增加 `deleted: "源已删除"`；
- 新增 `isSourceDeleted(status)` 判定，供形状渲染分支使用。

## 测试与验证

- `tests/insights.test.ts`：`isSourceRunning/isSourceDeleted/sourceStatusLabel` 对 `deleted` 的行为。
- `npm run typecheck`、`npm run lint`、`npm run test` 通过。
- 手动验证：`/ask` 完成问答 → 加入画布 → 勾选图表 + 新建/选择画布 → 自动跳转并按「一图一卡」出现实时卡片 → 刷新页面卡片仍在（snapshot 布局 + 绑定内容回灌）→ 删除卡片后绑定消失 → 删除源问答后卡片显示「源已删除」→ 卡片「打开来源」跳回 `/ask` 并加载原问答。

## 假设与说明

- 深链导入（跳转画布页自动建卡）优先于服务端拼 snapshot：形状 id 由 tldraw 客户端生成，避免服务端模拟 tldraw 内部结构。
- 旧 snapshot 中的卡片（无 `chartIndex`）按「全部图表」渲染（内部滚动），与新的一图一卡共存；`chartIndex` 越界（源图表变动）时同样回退为全部。
- 研究页（`/research`）本期不加"加入画布"按钮（画布导入面板已覆盖研究流入）；`AddToCanvasDialog` 组件保持通用，后续一行接入。
- 撤销删形状的边界场景接受"卡片退化为静态内容"，不做补偿。
- 遵循项目规范：中文注释、API 统一 `{ok, data}` / `{error:{code,message}}` 结构。
