## 一、项目概述

归因模块（Enterprise Intelligence Insight Platform）是一个基于 LangGraph 多 Agent 工作流的智能分析系统，旨在通过自然语言交互实现数据分析与深度研究，为企业提供实时、可溯源、可验证的业务洞察。

### 核心能力矩阵

| 能力 | 实现状态 | 验证方式 |
|------|----------|----------|
| LangGraph 多 Agent 工作流 | ✅ 已完成 | Supervisor→Workers→Critic→Synthesizer 全链路 |
| NL2SQL 数据分析 | ✅ 已完成 | 9 条真实 SQL（含同比 CTE）执行验证 |
| 深度研究工作流 | ✅ 已完成 | Planner→Executor→Synthesizer 端到端 290s |
| 算子管理系统 | ✅ 已完成 | 12 个算子（6 数据 + 6 研究）试运行 |
| 外部数据获取 | ✅ 已完成 | Web 搜索（Bing/DuckDuckGo）+ 网页深读 |
| 图表生成系统 | ✅ 已完成 | 6 种图型（Recharts）+ PNG 导出 |
| 数据源管理 | ✅ 已完成 | 连接测试 + Schema 内省 + 只读查询 |
| 语义层管理 | ✅ 已完成 | 语义模型浏览 + SemanticQuery→SQL 转译 |

## 三、已完成功能模块

### 3.1 LangGraph 多 Agent 工作流

**核心架构**：
- **Supervisor**：意图路由（data_analysis / research / direct_answer）
- **Data Analyst**：NL2SQL 分析（生成 SQL → 执行 → 展示表格 → 生成图表）
- **Researcher**：深度研究（搜索 → 深读 → 证据抽取）
- **Critic**：质量校验（评分 + 重试机制）
- **Synthesizer**：综合结论生成（流式输出）

**关键特性**：
- 工具预算控制（web_search 8 次 / fetch_page 6 页，超限强制转入 record_finding）
- 证据兜底机制（salvage 搜索摘要为 notes，防止无数据）
- 重试逻辑（Critic 首次失败允许补研究一次）
- SSE 事件流（meta/phase/step/tool_call/table/chart/chunk/citations/done）

**验证结果**：
- 数据分析路径：14 次工具调用、3 张图表、8 张表格、180s
- 研究路径：31 次搜索（预算拦截生效）→ 3 条发现 → Critic 4 分 → 诚实降级

### 3.2 深度研究工作流

**核心架构**：
- **Planner**：研究规划（拆解 3-5 子问题 + 检索关键词）
- **Executor**：逐子问题执行（搜索 2-3 轮 → 深读高价值页面 → 证据抽取）
- **Synthesizer**：报告生成（流式输出，含执行摘要/详细发现/综合分析/结论展望/证据缺口）

**关键特性**：
- CitationRegistry 全局引用去重编号
- 子任务持久化（每个子问题可追踪）
- 证据缺口诚实标注（找不到数据时不编造）
- SSE 事件流（plan/phase/step/tool_call/chunk/citations/done）

**验证结果**：
- 端到端测试：5 个子问题、20 次搜索/深读、42 条引用、3138 字报告、290s 完成
- 任务持久化：主任务 + 5 子任务 + 引用全部落库
- 历史回看：子问题发现/检索词/引用/全文报告完整展示

### 3.3 NL2SQL 数据分析

**核心流程**：
1. 意图路由（Supervisor 判断为 data_analysis）
2. Data Analyst 接管（加载 Schema → 生成 SQL → 执行 → 展示表格 → 生成图表）
3. Synthesizer 汇总（流式生成结论）

**关键特性**：
- 只读 SQL 安全（SELECT-ONLY + READ ONLY 事务 + statement_timeout + 行数上限）
- 语义层转译（SemanticQueryV1 → SQL，支持指标/维度/粒度/时间范围）
- 自动图表选型（根据数据特征选择 bar/line/area/pie/radar/composed）
- 表格数值格式化（number/percent/wan/compact）

**验证结果**：
- 端到端测试：9 条真实 SQL（含同比 CTE）、9 张表格、1 张折线图、232s
- 语义层转译：分组查询 + 月度趋势查询均返回真实数据

**相关文件**：
- `lib/server/agents/workers.ts` (Data Analyst 部分)
- `lib/server/semantic/semantic-query.ts` (368 行)

| 数据分析 | aggregate | SQL | 分组聚合（GMV/订单/用户） |

| 数据分析 | anomaly | SQL | 异常检测（Z-Score 滑动窗口） |
| 数据分析 | filter | SQL | 条件过滤（区域/渠道/日期） |
| 数据分析 | transform | SQL | 数据转换（单位换算 + 派生指标） |
| 数据分析 | join | SQL | 跨源关联（指标 vs 订单） |
| 深度研究 | search | Web | 多源检索（Bing/DuckDuckGo） |
| 深度研究 | extract | Hybrid | 信息抽取（LLM 抽取要点） |
| 深度研究 | summarize | LLM | 内容摘要（结构化/段落） |
| 深度研究 | compare | LLM | 多源对比（共识/分歧/置信度） |
| 深度研究 | citation | Web | 引用溯源（标题/URL/摘要） |
| 深度研究 | write | LLM | 报告写作（章节生成） |

## 五、验证中发现并修复的 Bug

### 5.1 语义层 SQL 子句顺序缺陷

**Bug class**：语义层 SQL 生成器产出的 SQL 语法错误（HTTP 500 INTERNAL_ERROR）

**Root cause**：`lib/server/semantic/semantic-query.ts` 中 `translateToSql` 采用分段拼接 SQL 字符串，拼接顺序写成 `SELECT→FROM→GROUP BY→WHERE→LIMIT`，违反 SQL 标准子句顺序（WHERE 必须在 GROUP BY 之前），PostgreSQL 直接抛语法错误。

**Fix pattern**：手写 SQL 拼接器时按固定模板顺序组装：`SELECT → FROM → WHERE → GROUP BY → ORDER BY → LIMIT`；条件块各自独立 if，不依赖调用方传入顺序。

**Reusable lesson**：字符串拼接生成 SQL 的模块必须有"转译→执行"的端到端试运行入口（API+UI）作为回归防线；仅靠下游 Agent 绕过该模块时 bug 会长期潜伏。

### A.2 语义层 SQL 生成

```typescript
// lib/server/semantic/semantic-query.ts
export function translateToSql(query: SemanticQueryV1): TranslatedQuery {
  const model = findModel(query);
  const selectParts: string[] = [];
  const groupParts: string[] = [];

  for (const dim of query.dimensions) {
    const dimDef = model.dimensions.find((d) => d.id === dim.dimensionId);
    const expr = TIME_GRANULARITY_SQL[dim.granularity]?.replace("{col}", dimDef.column);
    selectParts.push(`${expr} AS ${quoteIdent(dimDef.id)}`);
    groupParts.push(expr);
  }

  for (const m of query.metrics) {
    const metricDef = model.metrics.find((x) => x.id === m.metricId);
    selectParts.push(`${metricDef.agg.toUpperCase()}(${quoteIdent(metricDef.column)}) AS ${quoteIdent(m.alias ?? metricDef.id)}`);
  }

  let sql = `SELECT ${selectParts.join(", ")}\nFROM ${quoteIdent(model.schema)}.${quoteIdent(model.table)}`;
  if (conditions.length > 0) sql += `\nWHERE ${conditions.join(" AND ")}`;
  if (groupParts.length > 0) sql += `\nGROUP BY ${groupParts.join(", ")}`;
  if (query.sort) sql += `\nORDER BY ${query.sort.map((s) => `${quoteIdent(s.field)} ${s.direction.toUpperCase()}`).join(", ")}`;
  sql += `\nLIMIT ${query.limit ?? 200}`;

  return { model, sql, columns: selectParts.map((p) => p.split(" AS ").pop()), notes };
}
```

// components/charts/ChartRenderer.tsx
export function ChartRenderer({ spec, height = 300 }: { spec: ChartSpec; height?: number }) {
  const containerRef = useRef<HTMLDivElement>(null);

  const exportPng = useCallback(() => {
    const svg = containerRef.current?.querySelector("svg");
    const serializer = new XMLSerializer();
    const svgStr = serializer.serializeToString(svg);
    const canvas = document.createElement("canvas");
    const ctx = canvas.getContext("2d");
    const img = new Image();
    img.src = "data:image/svg+xml;base64," + btoa(svgStr);
    img.onload = () => {
      canvas.width = img.width * 2;
      canvas.height = img.height * 2;
      ctx?.drawImage(img, 0, 0, canvas.width, canvas.height);
      const link = document.createElement("a");
      link.download = `${spec.title}.png`;
      link.href = canvas.toDataURL("image/png");
      link.click();
    };
  }, [spec.title]);

  return (
    <div ref={containerRef}>
      <ResponsiveContainer width="100%" height={height}>
        {renderChart(spec)}
      </ResponsiveContainer>
      <button onClick={exportPng}>导出 PNG</button>
    </div>
  );
}
