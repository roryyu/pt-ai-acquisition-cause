## 二、实施方案与结果

实施顺序：**③ 退避重试 → ④ 时区 → ② 同步模块化 + 定时入口 → ⑤⑥ JSON 终端与 slug 校验 → 测试回归**。

### 2.1 ③ 429 指数退避 + Retry-After（`lib/server/connectors/api.ts` + `api-cache.ts`）

- `api.ts` 新增 `parseRetryAfterMs`（纯函数）：支持秒数（`120`）与 HTTP-date 两种格式，已过期/非法返回 `undefined`；`fetchWithLimits` 在 429/503 时读取 `retry-after` 头部，`ApiCallResult` 透出 `retryAfterMs`
- `api-cache.ts` 新增 `computeBackoffMs`（纯函数）：**优先遵循上游 Retry-After**，否则指数退避 `500ms × 2^attempt` + 0~250ms 随机抖动，上限 10s
- `cachedRestRequest` 实时请求阶段：429/5xx **先退避重试（最多 2 次）**，仍失败才走既有 stale-while-error 降级；200ms 同源最小间隔保留
- 同步模块（见 2.3）的直连 fetch 复用同一套 `computeBackoffMs` + `parseRetryAfterMs`

### 2.2 ④ 时区口径统一（`lib/env.ts` + 同步模块 + 算子层）

- 新增环境变量 `ADJUST_RS_UTC_OFFSET`（格式 `±HH:MM`，缺省 `+08:00`，与本地经营数据对齐）；`ADJUST_API_TOKEN` / `ADJUST_RS_API_BASE_URL` 同步纳入 env Schema（此前仅脚本裸读 `process.env`）
- 同步拉数与算子层 `fetchApiReportRows` 的 API 直查均携带 `utc_offset`，落库口径与直查口径一致
- ⚠️ **口径切换提示**：此前已同步的历史数据为 UTC 口径，切换 `+08:00` 后需重跑一次较大窗口同步对齐（如 `npx tsx scripts/sync-adjust-data.ts --days 30`），已写入 `.env.example` 注释

### 2.3 ② 同步模块化 + 定时入口（前序遗留 B-3 完成）

**模块化**（新增 `lib/server/integrations/adjust-sync.ts`）：

- 脚本全部同步逻辑下沉为可复用模块，导出 `runAdjustSync(options)` / `AdjustSyncResult`；DB 访问改走项目统一 `prisma` 单例（`$executeRawUnsafe` / `$queryRawUnsafe` 参数化，不再自建 `pg` 连接，遵守 `lib/db` 单例约定）
- `scripts/sync-adjust-data.ts` 瘦身为薄壳（231 行 → 33 行）：仅加载 `.env`、解析 `--days`、转发日志；动态 `import()` 保证 `.env` 先于 env 校验加载
- 新增 `AdjustSyncConfigError`（凭证缺失），供 API 层映射 503

**定时入口**（新增 `app/api/v1/syncs/adjust/route.ts`）：

- `POST /api/v1/syncs/adjust`，入参 `{ days?: number }`（zod 校验 1~90）；沿用项目「无常驻定时器、外部驱动」约定（与 `/api/v1/schedules/run` 一致）
- 外部 cron 挂接方式（已写入路由注释与 `.env.example`）：
  ```
  30 9 * * * curl -X POST http://localhost:3000/api/v1/syncs/adjust -d '{"days":3}'
  ```
  Adjust 数据 T+1，每日上午拉昨日 + 回补 3 天覆盖修正窗口；幂等可重跑

### 2.4 ⑤ JSON 终端 totals 利用（`lib/server/operators/data-operators.ts`）

- 算子层统一取数分流 `fetchApiReportRows` 从 `csv_report` 切换为 **JSON 终端 `report`**：额外获得 `totals`（区间总量，写入 notes 供口径交叉校验）与 `data_warnings`（上游数据预警，写入 notes）
- `apiBodyToTable` 对 CSV/JSON `{rows}` 双格式兼容保留（`query_api_source` 自由探索仍可能返回 CSV）
- 缓存键含 path，切换终端后旧缓存自动失效，无需清理

### 2.5 ⑥ 事件 slug 动态校验（同步模块）

- 每次同步先请求 `/events` 终端，校验 `register_events` / `firstdeposit_events` / `recalldeposit_events` 对应事件是否存在；**缺失仅预警（warnings）不阻断同步**
- 实测确认 `/events` 真实结构：`[{ id, name, app_token, tokens, ... }]`，`id` 为裸事件名，**报表指标 slug 约定为 `{事件id}_events`**（如 `register_events` ← 事件 `register`）——指南未写明该约定，首轮按 `*_events` 全文匹配产生误报，已按实测修正
- `parseEventIds`（纯函数）：优先按 JSON 数组取各项 `id`（解析成功即信任，无有效 id 也不回退全文匹配避免误报），非 JSON 回退全文匹配
