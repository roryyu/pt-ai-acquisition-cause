## 二、Review 结论（实测证据）

用现有连接器代码（`lib/server/connectors/api.ts`）直连 Adjust 真实 API 验证：

### 2.1 配置模型层面：够用

| Adjust RS API 需求 | 现有能力 | 实测 |
|---|---|---|
| Bearer Token 认证 | `authType: "bearer"` + `authToken` | ✅ 200 |
| GET + 复杂 query（`dimensions=day,network`、`date_period=2026-09-01:2026-09-01`、`country_code__in=ph,th` 等 `__` 过滤操作符） | `params` 经 URLSearchParams 编码 | ✅ 逗号/冒号/双下划线均正常 |
| CSV 响应（非 JSON） | `parseBody` 非 JSON 保留原文 | ✅ `text/csv; charset=utf-8-sig` 完整返回 |
| 连通性测试 | base URL 404 但 `status < 500` 判可达 | ✅ `ok:true` |
| 注册校验 | `CreateDataSourceSchema` api 分支覆盖所需字段 | ✅ |

注册配置（① 修复后 endpoint 尾斜杠不再必需，见 §五）：

```json
{ "type": "api", "name": "Adjust 报告服务",
  "endpoint": "https://automate.adjust.com/reports-service/",
  "protocol": "rest", "authType": "bearer", "authToken": "<ADJUST_API_TOKEN>" }
```

### 2.2 实测发现的缺口

| # | 严重度 | 缺口 | 证据 |
|---|---|---|---|
| ① | 🔴 | `resolveRequestUrl` 用 `new URL(path, base)`：path 带前导 `/` 或 endpoint 无尾斜杠时 **base path `/reports-service` 丢失** → 404；唯一可用组合是「尾斜杠 endpoint + 无前导斜杠 path」，而工具 schema 示例恰为 `/v1/users`，LLM 必然踩坑 | 实测 3 种组合：仅 A 成功，B/C 均 404 |
| ② | 🔴 | 任务问答（`data_analysis` 路由）的 DataAnalystWorker 未挂载 `query_api_source`（仅 ResearchWorker 接入，设计文档既定约定） | `workers.ts` 工具列表 |
| ③ | 🟡 | CSV 无结构化层：原始字符串进 LLM 上下文并在 20K 字符硬截断；BOM、`readable_names` 本地化表头未处理 | `tools.ts` `slice(0, 20_000)` |
| ④ | 🟡 | design.md §5.1.2 要求的 API 适配器能力「限流、熔断、幂等、缓存」均未实现 | `api.ts` 仅超时+截断 |
| ⑤ | ⚪ | Parquet 端点不可用（`response.text()` 损坏二进制，PAR1 魔数丢失）；走 CSV/JSON 即可 | 实测 |

**结论**：修复 ① 后「注册 + 调试台 + 深度研究」即可使用 Adjust；「任务问答做数据分析」需按 ②③④ 补齐。

### 2.3 Adjust 数据能力边界（测试确认）

- 终端：`/csv_report`（CSV）、`/report`（JSON `{rows, totals, data_warnings}`）、`/pivot_report`（必传 `index`）、`/parquet_report`；`/json_report` 为 404
- 认证：Bearer（API 识别码）；速率限制 50 req/s/IP、突发 100；数据 T+1
- 昨日实测：总安装 542,115（web 331,149 / gadmobe-apk 59,565 / Organic 22,196 …）

## 三、实施方案

实施顺序：**① URL 修复（阻塞项）→ B 落库与语义挂载 → C 缓存 → A-2 问答接入 → A-1 算子化**。

### 3.1 ① 修复 `resolveRequestUrl`（`lib/server/connectors/api.ts`）

- 拼接语义改为 **base.pathname 保留**：`path` 去除前导 `/` 后追加到 endpoint 路径（endpoint 无尾斜杠自动补），仍校验结果 origin 不变
- 兼容既有语义：endpoint 为纯域名（pathname=`/`）时行为与原先一致
- 工具 schema 中 `path` 描述同步为「相对路径（如 v1/users 或 /v1/users 均可）」

### 3.2 B 本地数据更新：Adjust → PG → 语义层（问答主链路走本地）

**B-1 落库**（新增 `scripts/sync-adjust-data.ts`，参照 `seed-acquisition-data.ts` 幂等模式）：

- 新表 `demo.adjust_daily_metrics`：`stat_date × network × country_code` 粒度；指标列 `impressions / clicks / installs / sessions / register_cnt / first_deposit_cnt / recall_deposit_cnt / network_cost`（与 Adjust slug 对齐，成本列可空——当前账号无支出数据）
- 拉取 `/csv_report`（`dimensions=day,network,country_code`，默认近 3 天回补 + 昨日，`--days N` 可调）→ CSV 解析（去 BOM）→ `ON CONFLICT (stat_date, network, country_code) DO UPDATE` 幂等 upsert
- CSV 解析纯函数下沉 `lib/server/connectors/csv.ts`（`parseCsvTable`：BOM 剥离、表头/行解析、数值列推断），供脚本与 A-1 算子共用、可单测

**B-2 语义挂载**（脚本内同步写入，幂等先删后插）：

- `cause.semantic_models` 新增自定义模型「Adjust 投放日指标」：`dataSourceId=null`（走内置演示 PG）、`tableRef=demo.adjust_daily_metrics`、`fields` 定义指标/维度（口径见 Adjust 文档）
- 现有机制下 `run_operator` 指标/维度目录自动纳入，任务问答即可用本地算子/SQL 分析真实 Adjust 数据，并可与 `demo.channel_daily_metrics` 对比
- `cause.metrics` 补录 Adjust 口径指标定义（installs / clicks / impressions / FD 数 / RD 数）

**B-3 定时刷新**：复用 `lib/server/scheduler.ts` 轮询注册每日同步 job（Adjust 数据 T+1，每日拉昨日+回补 3 天），失败记录日志不阻断

### 3.3 C API 查询缓存（落 PG，遵循 design.md §6.3「Redis 未实施、PG 为当前替代」）

- Prisma 新模型 `ApiQueryCache`（`cause.api_query_cache`）：`id / source_id / cache_key / method / url / status / content_type / body(Text) / elapsed_ms / hit_count / created_at / expires_at`；`cache_key = sha256(method + 完整 URL + params 按 key 排序)`，唯一索引
- 新增 `lib/server/connectors/api-cache.ts`：`cachedRestRequest(config, input, { sourceId, ttlSeconds })` 包装 `executeRestRequest`——命中未过期直接返回（标注 `fromCache`）；未命中请求后写入；上游 429/5xx 且存在过期缓存时**降级返回旧值**（stale-while-error）
- TTL 策略（适配 T+1）：`date_period` 结束日早于今天 → 7 天；含今天/昨天 → 30 分钟；无法识别 → 默认 1 小时
- 简单限流：同一 source 内存令牌桶（≥200ms 间隔），429 时读 `Retry-After` 退避
- `query_api_source` 工具与 A-1 算子统一走 `cachedRestRequest`

### 3.4 A-2 任务问答接入 API（最小改动打通）

- `runDataAnalystWorker` 按 ResearchWorker 同款模式：`loadExternalSources()` → 非空时 `tools.push(createApiSourceTool(ctx, apiSources))`
- `prompts.ts` 新增 `dataAnalystExternalSourcesBlock`（追加到 `buildDataAnalystPrompt` 结果后）：列出可用 API 源，约定「本地表优先、API 仅补充本地缺失的维度/时间范围；Adjust 源 path 用 `csv_report` 形式」
- MCP 源不接入 DataAnalyst（保持职责边界，研究链路专用）

### 3.5 A-1 `api_fetch` 数据算子（算子化终态）

- `lib/server/operators/data-operators.ts` 新增 `ApiFetchOpMeta / ApiFetchInput / runApiFetchOp`：入参 `{ sourceId, path, dimensions, metrics, datePeriod, filters?, sortBy?, limit? }` → `cachedRestRequest` 拉 CSV → `parseCsvTable` 结构化 → 输出 `OperatorRunResult`（columns/rows，行数截断 200 并 notes 提示）
- `registry.ts` 注册 `api_fetch`（静态 Schema，同研究算子模式）；`run` 内部 `listDataSources()` 解析源配置
- `createRunOperatorTool` 的算子清单描述自动包含 `api_fetch`；`buildDataAnalystPrompt` 算子场景映射补一条「本地缺失的 Adjust 实时/细粒度数据 → api_fetch」

## 五、实施结果（2026-09-02 回填）

全部开发项完成，全量回归通过：**vitest 130/130（11 文件，较实施前 +21 用例）、`tsc --noEmit` 零错误、改动文件 eslint 零告警**。

### 5.1 ① URL 修复（api.ts）

- `resolveRequestUrl` 改为 base path 拼接语义：`path` 剥离前导 `/` 后追加到 endpoint 路径末尾（无尾斜杠自动补），origin 变化守卫保留
- 实测回归：「endpoint 含 base path × path 三种写法」均拼为 `/reports-service/csv_report`；纯域名 endpoint 行为与标准相对路径解析一致
- 行为变化同步旧测试：跨主机写法（`https://evil.com/x`、`//evil.com/x`）不再抛错，而是被中和为同主机子路径（无法跨主机重定向，守卫成为防御性兜底），`tests/datasources.test.ts` 两个旧用例已更新断言

### 5.2 B 落库 + 语义挂载 + 算子层动态化

- `scripts/sync-adjust-data.ts` 实跑成功：`demo.adjust_daily_metrics` 库内 **7 天 / 12,371 行 / 总安装 3,927,583 / 总 FD 176,940**；幂等重跑验证通过（upsert 5,289 行无副作用）
- 昨日渠道分布（同步验证输出）：web 331,153 installs / 21,610 注册 / 11,672 FD；gadmobe-apk 59,565；Organic 22,199（FD 5,239 ≈ 注册 5,514，自然量质量最高）
- 语义模型 `semantic_model_adjust_daily`（「Adjust 投放日指标」，8 指标 3 维度）已挂载并**关联到已注册的 Adjust API 数据源**（血缘可追溯；未注册时回退 NULL 走内置演示库）；`cause.metrics` 补录 5 个 Adjust 口径指标
- 算子层运行时动态目录（B-2b）：`runtimeSemanticModels()` = 内置 + DB 自定义合并（DB 不可用降级内置）；4 个 run* 函数改用动态模型集；Schema 的 metric/model 由 `z.enum` 放宽为 `z.string()`（运行时按动态目录校验，错误信息同样明确：「未知指标: xxx」），静态枚举保留供 UI 提示

### 5.3 C 查询缓存（api-cache.ts + cause.api_query_cache）

- Prisma `ApiQueryCache` 模型已 `db push` + `generate`；`cachedRestRequest` 实现 fresh 命中 / miss 写入 / 上游异常或 429/5xx 时 stale 降级 / 缓存读写失败降级直连
- TTL 策略（`resolveTtlSeconds` 纯函数，已单测）：含今天/昨天 → 30 分钟；结束日距今 ≥2 天 → 7 天；无 date_period → 1 小时
- 限流：同源内存最小调用间隔 200ms（单实例够用，无外部依赖）
- **真实端到端冒烟**：注册「Adjust 报告服务」数据源后，`api_fetch` 首次真实拉数 2,272ms（10 行结构化），二次调用 **5ms 命中缓存**，`api_query_cache` 落库 1 条

### 5.4 A-2 问答接入（workers / tools / prompts）

- `runDataAnalystWorker` 并行加载：外部数据源 + 运行时全量数据字典（`runtimeTablesHint`，含 Adjust 模型）+ 运行时算子目录描述（`runtimeRunOperatorToolDescription`）；有 API 源时动态挂载 `query_api_source`
- `query_api_source` 工具：REST 分支改走 `cachedRestRequest`（命中缓存不消耗上游配额）；CSV 响应经 `parseCsvTable` 结构化为表格行返回（最多 200 行，避免原文占满 20K 截断窗口）；path 参数描述同步拼接新语义
- `prompts.ts` 新增 `dataAnalystExternalSourcesBlock`（本地表优先、api_fetch 报告取数、query_api_source 兜底、T+1 提醒）；算子优先规则补「本地表没有的外部实时/细粒度数据 → api_fetch」

### 5.5 A-1 `api_fetch` 算子（第七个数据算子）

- `data-operators.ts` 新增 `ApiFetchOpMeta / ApiFetchInput / buildApiFetchParams / runApiFetchOp`（engine=`"api"`）；`registry.ts` 注册；`OperatorMeta.engine` 联合扩展 `"api"`
- 行为：filters 直接并入 query（支持 `__in/__gte` 操作符）；CSV → 对象行（JSON `{rows}` 响应也兼容）；204 → ok + 空行 + 「区间无数据」；非 2xx → 失败含状态码与响应摘要；>200 行截断并 notes 提示；缓存状态（fresh/stale）写入 notes
- `DATA_OPERATOR_IDS` 与工具描述同步七算子
