# Adjust 官网使用情况评估与价值分析

> 评估日期：2026-09-02
> 评估账号：Rory Yu（角色：**读者**）| 组织：PLAYMATE LEISURE SOLUTIONS CORP.
> 结论先行：**Adjust 目前只发挥了约 30%~40% 的价值——"归因报表工具"用起来了，但"ROI 优化引擎"和"反作弊防线"两大核心价值基本闲置。**

---

## 一、总体判断

Adjust 的价值链条是：**归因（谁带来的用户）→ 成本收入关联（值不值）→ 优化决策（钱往哪投）→ 欺诈防护（别被骗）**。

当前使用情况：

| 价值环节 | 使用情况 | 评价 |
|---|---|---|
| 归因追踪（展示/点击/安装/事件） | 深度使用 | ✅ 充分发挥 |
| 渠道质量对比（转化率/留存） | 中度使用 | ✅ 基本发挥 |
| 成本与收入分析（ROAS/ROI/CPI） | **未使用** | ❌ 严重缺失 |
| 反作弊防护 | **未使用** | ❌ 严重缺失 |
| 自动化（API/定时报告） | 未使用 | ⚠️ 有潜力 |
| 投放工具（Campaign Lab） | 无权限 | ⚠️ 受限于账号角色 |

**一句话结论：团队把 Adjust 当"数据查询器"用，而没有当"投放决策系统"用。**

## 二、支撑证据

### 证据 1：广告支出和收入数据全是 0（最关键）

概览看板近 7 天数据：**广告支出 0.00、所有收入 0.00**；安装后同期群指标中所有渠道的 1D/3D/7D 单用户收入、ROI、毛利全部为 0。

这意味着：

- 没有接入任何渠道的花费数据（cost integration），无法计算 CPI/eCPI；
- 没有回传任何收入事件（revenue event），ROAS/LTV 分析完全失效；
- **最核心的问题**：每天 4 万安装、3,900 万周安装，但无法回答"哪个渠道的用户更值钱、该加预算还是砍预算"——这正是投放归因平台最值钱的输出。

### 证据 2：反作弊能力闲置

保护看板（被拒安装、交互作弊、不受信任设备、分布监测等 10 个组件）存在，但未见任何主动使用痕迹（无相关收藏报告）。而概览中 **Untrusted Devices 渠道近 7 天有 27,297 个安装**，占总安装 0.7%，说明作弊/异常流量是真实存在的，却没有人盯。

### 证据 3：账号权限是最低档"读者"

- 个人档案显示角色为**读者**（只读）；
- Campaign Lab 三个工具（自定义链接/深度链接/链接调试）返回 403；
- 应用配置菜单（平台/事件/测试控制台/服务器回传/云储存上传）全部禁用。

作为读者账号无法推动上述任何改进（接成本、配事件、加回传），**价值提升的前提是先解决权限或找到管理员**。

### 证据 4：报告使用活跃但停留在"拉数"层面

- 17+ 个共享报告全部是"维度 + 漏斗指标"型日报（Hatti-Daily、Anna、Ian-Daily 等），最后修订集中在 2026/07/13~08/26，有人日常维护；
- 指标集中在展示/点击/安装/注册/首存的**数量与转化率**，没有一份报告涉及 cost、ROAS、留存价值；
- 主页收藏仅 1 份报告（Hatti-Daily），且"已定时"为**否**——定时自动发送报告功能未启用，日报大概率靠人工导出。

### 证据 5：资产治理缺失

- 10+ 个应用处于"等待中"状态（0 安装）：EGgame、Foodpanda、GooglePlay、Grab 等，疑似历史测试残留，未清理；
- SDK 版本不统一：Honor 用 v5.7.0，Transsion/appdownload 仍在 v4.38.3（v4 已属旧版）；
- appdownload 近 7 天安装环比 **-40.24%**，未见任何归因分析动作；
- 资源中心 57 条未读通知，帮助中心功能未被利用。

## 三、价值提升建议（按优先级）

### P0 — 打通"钱"的数据（收益最大）

1. **接入广告花费**：为 Facebook、Google、华为、OPPO、Vivo、小米等主要渠道配置 cost data 集成（需要管理员权限），立刻可算出各渠道 CPI；
2. **回传收入事件**：在客户端埋点充值金额并映射为 revenue 事件，激活 ROAS/LTV 同期群分析；
3. 建成后在概览/报告中增加 **CPI、ROAS D1/D7、毛利** 列，投放决策从"看量"升级为"看回报"。

### P1 — 启用反作弊监控

4. 将保护看板关键指标（被拒安装率、不受信任设备）做成周报或设置异常提醒；
5. 对 Untrusted Devices 占比异常的渠道与渠道方对质，避免为假量付费。

### P2 — 自动化与提效

6. 利用账户设置中的 **API 识别码**，通过 Adjust Reporting API 自动拉取日报数据，接入内部数据平台/BI（可与 `pt-ai-acquisition-cause` 项目的数据源 API 设计结合）；
7. 开启报告**定时发送**（邮件日报），替代人工导出；
8. 清理僵尸应用、统一升级 SDK 至 v5（v5 支持更好的隐私合规与新归因能力）。

### P3 — 权限与协作

9. 向组织管理员申请将账号升级为可编辑角色（至少"分析师"），否则上述配置类动作全部无法执行；
10. 建立报告命名与所有权规范（当前报告命名随意，如"Anna""拉数-888"），沉淀标准指标口径。

## 四、评估结论

| 维度 | 评分（5 分制） | 说明 |
|---|---|---|
| 归因数据利用 | 4 | 漏斗指标日常在用 |
| 商业价值挖掘 | 1 | 成本/收入/ROI 全缺失 |
| 风险防护 | 1 | 反作弊看板闲置 |
| 自动化程度 | 1 | 无 API 取数、无定时报告 |
| 资产治理 | 2 | 僵尸应用、SDK 版本混乱 |
| **综合** | **~1.8 / 5** | 仅发挥"查询器"价值，远未达到"决策引擎"水平 |
