### 4.4 API 路由规范

```typescript
// 标准 API 路由模板
import { z } from "zod";
import { ApiError, handleApiError, ok, readJson, requireActor } from "@/src/server/runtime";

const RequestSchema = z.object({ /* ... */ });

export async function POST(request: Request, context: { params: Promise<{ id: string }> }) {
  try {
    const actor = await requireActor(request);
    const input = RequestSchema.parse(await readJson<unknown>(request));
    // 业务逻辑...
    return ok({ /* 响应数据 */ });
  } catch (error) {
    return handleApiError(error);
  }
}
```

**关键模式：**
- 所有路由使用 `try/catch` + `handleApiError` 统一错误处理
- 请求体验证使用 Zod Schema 的 `.parse()` 方法
- 身份验证通过 `requireActor(request)` 完成
- 成功响应使用 `ok(data, status?)` 返回 `{ ok: true, data }`
- 错误响应返回 `{ ok: false, error: { code, message, retryable, requestId } }`
- 动态路由参数通过 `context.params`（Promise）获取

### 4.5 错误处理规范

```typescript
// ApiError 类 — 统一错误结构
class ApiError extends Error {
  status: number;       // HTTP 状态码
  code: string;         // 错误码（大写蛇形）
  retryable: boolean;   // 是否可重试
  details?: unknown;    // 附加信息

      setLoading(false);
    }
  }, [t]);

  useEffect(() => { refresh(); }, [refresh]);
  // ...
}
```

**模式要点：**
- 状态管理使用 `useState` + `useCallback`
- 翻译函数通过 `useMemo` 缓存
- 数据获取使用 `useEffect` 触发
- 错误展示使用 `error` 状态 + `role="alert"`
- 加载中展示使用 `loading` 状态 + `role="status"`
- i18n key 使用 Record 常量集中管理（如 `STATUS_KEYS`、`CONTROL_COPY`）

#### CSS Modules 使用规范

- 每个页面/组件配套一个 `*.module.css` 文件
- 通过 `import styles from "./page.module.css"` 引入
- 使用 `className={styles.xxx}` 绑定样式类
- 组件内的全局样式通过 `:global(.class-name)` 选择器穿透
- 页面级 CSS 变量在 `.page` 选择器内定义（作用域隔离）

#### i18n 集成

- 所有用户可见文本使用 `data-i18n="key"` 属性标记（HTML）或 `t("key")` 函数（React）
- 支持复数、模板插值、货币/日期/数字格式化
- `aria-label` 也支持国际化：`data-i18n-aria-label="key"`
