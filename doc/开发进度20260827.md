## 二、核心改造内容

### 2.1 深度研究工作流算子化（`lib/server/agents/deep-research.ts`）

改造后的工作流结构：

```
Planner（研究规划：拆解 3-5 个子问题 + 检索关键词）
  → Executor（逐子问题：SearchOp 多轮检索 → ExtractOp 深读抽取 → 证据整合）
  → Analyzing（CompareOp 多源交叉比对：共识 / 分歧 / 置信度）★新增阶段
  → Synthesizer（汇总全部证据，流式生成结构化研究报告）
```

| 工作流环节 | 改造前 | 改造后 |
|---|---|---|
| 多轮检索 | 直连 `webSearch(query, 6)` | `runOperator("search", { query, maxResults: 6 })`，结果行归一化为检索命中 |
| 深读高价值页面 | `fetchPage` 抓原始正文 | `runOperator("extract", { url, focus: 子问题 })`，材料从原始正文升级为**聚焦子问题的结构化要点** |
| 多源交叉比对 | 无 | 新增 `compareResearchEvidence`：调 `runOperator("compare", { sources, topic })`，比对全部子问题发现，结论以「多源比对结论（CompareOp 算子）」块注入报告生成输入 |
| 证据整合 / 报告生成 | EXTRACTOR_PROMPT / REPORT_PROMPT（跨材料带引用编号整合、流式成稿） | 保持不变（算子无法替代，见 2.3 决策） |

**状态机扩展**：`onStateChange` 联合类型新增 `"analyzing"`，状态流转变为 `planning → collecting → analyzing → writing → completed`（Prisma `ResearchState` 枚举本就包含 `analyzing`，**无需数据库迁移**）。

### 2.2 失败降级策略（全部静默降级，不阻断任务）

| 场景 | 降级行为 |
|---|---|
| `search` 算子失败 | 记录检索失败事件，继续下一组关键词；无证据时子问题走「未检索到能直接回答」兜底发现 |
| `extract` 算子失败 | 记录抽取失败事件，保留该来源的搜索摘要材料 |
| `compare` 算子失败 / 证据不足 | 跳过比对块，报告照常生成 |
| 无证据兜底发现 | 不触发 compare（避免拿兜底文案做无意义比对） |

### 2.3 关键设计决策：仅接入 search / extract / compare 三算子

| 算子 | 是否接入 | 原因 |
|---|---|---|
| SearchOp（多源检索） | ✅ | 替代直连检索，统一经注册表调度 |
| ExtractOp（信息抽取） | ✅ | 深读 + 聚焦子问题抽取要点，替代原始正文抓取 |
| CompareOp（多源对比） | ✅ | 填充 analyzing 阶段，共识/分歧/置信度进入报告综合分析 |
| SummarizeOp（内容摘要） | ❌ | 证据已由 ExtractOp 要点化压缩，二次摘要无增益 |
| CitationOp（引用溯源） | ❌ | 会重复发起检索；引用编号已由 CitationRegistry 增量去重登记 |
| WriteOp（报告写作） | ❌ | 定长（300-500 字）非流式段落生成器，无法替代流式完整报告（REPORT_PROMPT） |
